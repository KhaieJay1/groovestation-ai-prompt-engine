# GROOVESTATION PRO: MUSIC CONSISTENCY & MONETIZATION FRAMEWORK
*(Business + Technical Specification)*

## MODULE 1 — PROMPT CONSISTENCY FRAMEWORK (FOUNDATION)
### Purpose
Ensure all generated music within a channel or brand is **sonically consistent**, repeatable, and algorithm-friendly.
*   Consistency > novelty for monetization.

### 1.1 Core Concept: “Sound Lock”
Each channel operates under a **Sound Lock Profile**.
A Sound Lock Profile is a **non-negotiable constraint set** that governs all music generation.

**Components:**
1.  **Genre Spine**: One primary genre only.
2.  **Tempo Band**: Fixed BPM range (e.g. 98–104 BPM).
3.  **Instrumentation Lock**: REQUIRED/FORBIDDEN instruments.
4.  **Energy Ceiling**: Numeric energy range (e.g. 5–6/10).
5.  **Mood Vocabulary**: Allowed adjectives only.
6.  **Vocal Policy**: Instrumental / minimal / none.

### 1.2 Prompt Architecture (Technical)
All prompts are constructed using **fixed sections**:
`[CORE GENRE] [ENERGY & TEMPO] [INSTRUMENTATION] [MOOD & ATMOSPHERE] [STRUCTURE RULES] [NEGATIVE CONSTRAINTS]`

**Enforcement Rule:**
*   User cannot submit free-text prompts.
*   Prompt must be generated through the framework.

## MODULE 2 — “GOOD ENOUGH TO MONETIZE” STANDARD
### 2.1 Minimum Monetization Quality (MMQ)
A track is considered monetizable only if it passes **all checks**:
1.  **Consistency Match**: Matches Sound Lock Profile ≥ 90%.
2.  **Listening Fatigue Risk**: No abrupt changes/dominant leads.
3.  **Loop Tolerance**: Can loop 30–60 minutes.
4.  **Volume Balance**: No clipping.
5.  **Genre Integrity**: Immediately recognizable.

### 2.2 Technical Enforcement
*   Flag tracks that break rules.
*   Require regeneration before video rendering.
*   **Business Rule**: If music fails MMQ, GrooveStation Pro does not render it.

## MODULE 3 — PREMIUM TIER (ACCESS CONTROL)
### 3.1 Tier Structure
*   **Tier A (Core)**: Locked profiles, no editing. (Target: Beginners).
*   **Tier B (Advanced)**: Parameter adjustments, batch generation.
*   **Tier C (Pro)**: Full control, custom sound locks.

### 3.2 Exclusion Mechanism
Low-quality operators filtered by forced onboarding tests and locked defaults.

## MODULE 4 — MUSIC-FIRST ONBOARDING (DISCIPLINE ENGINE)
### 4.1 Onboarding Sequence
1.  **Education**: Acknowledge "Consistency > Creativity".
2.  **Sound Lock Selection**: One genre, one tempo.
3.  **Validation Generation**: Generate 3 samples. If rejected, stop.
4.  **Commitment Gate**: User confirms long-term commitment.
